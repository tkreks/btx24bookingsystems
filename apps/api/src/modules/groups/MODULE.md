# groups

**Назначение:** настройки групп (направлений) и приложения — данные нашей БД.

| Маршрут                                                          | Кто                | Что                                                    |
| ---------------------------------------------------------------- | ------------------ | ------------------------------------------------------ |
| `GET /api/groups`                                                | любой пользователь | его группы: роль, права, ресурсы (`MyGroupDto`)        |
| `GET/POST /api/admin/groups`, `PUT/DELETE /api/admin/groups/:id` | админ приложения   | список, создание, полная замена, архивирование         |
| `GET/PUT /api/admin/settings`                                    | админ приложения   | переключатели сбора данных диалогов, список `AppAdmin` |

**Инварианты**

- Тела запросов — zod (`groups.schemas.ts`, `.strict()`: лишние поля вроде `portalId` отвергаются);
  `portalId` всегда из контекста пользователя.
- `PUT` группы — полная замена настроек, ресурсов и участников одной транзакцией.
- Удаление — архивирование (`archivedAt`), не физическое.
- Сбор текстов диалогов нельзя включить без сбора метаданных; оба по умолчанию выключены.
- Диапазоны дублируются CHECK-ограничением в БД (`WorkGroup_ranges`).

## Экран настроек

Кнопка ⚙ календаря открывает разделы «Группы», «Приложение», «Прямая ссылка», «Встройки».
Доступен администраторам приложения (`SessionInfo.canManageApp`); серверные guards остаются
обязательными для каждого маршрута. Создание/редактирование — все основные настройки группы,
ресурсы, воронка, функции, сотрудники и отделы с ролями. Удаление в UI — архивирование.
Скрытые в форме `options` (оплаты, товары, поля сделки) сохраняются целиком, без потери импорта.
Несохранённые изменения требуют подтверждения перед выходом; незавершённый запрос блокирует
закрытие формы. После сохранения обновляются группы и календарь.

- `GET /api/admin/group-directory` — ресурсы `booking.v1.resource.list`, воронки
  `crm.category.list` (`entityTypeId: 2`), отделы `department.get`, имена уже назначенных
  сотрудников через `user.get` (`FILTER.ID`, только id из групп/администраторов этого портала); все страницы и только
  **клиентом пользователя**, без кэша между пользователями/порталами. Нет прав на отделы —
  `departmentsAvailable: false`, назначение сотрудников через `BX24.selectUsers` остаётся.
  Ошибки токена, сети и лимитов не превращаются в пустой список отделов.
- `GET /api/admin/external-users` — только id, логин, роль и признак отключения текущего
  портала; хеши паролей не возвращаются.
- `PUT /api/admin/external-users/:id/password` — `{ password }`, 12–128 символов, `204`;
  проверка и запись ограничены `portalId`, пароль хешируется существующим scrypt.
  Автоматической смены паролей импортированных пользователей нет.

Все три маршрута защищены `B24AuthGuard` и `AppAdminGuard`. Новых scopes и миграций нет.
Настройки хранятся в нашей БД и доступны в режиме чтения Битрикс24; портал экран не изменяет.
