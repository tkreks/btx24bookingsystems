# access

**Назначение:** кто что может — группы пользователя, роль, права (ADR 0005). `GET /api/session`
(в т.ч. `canManageApp`).

**Инварианты**
- Право в группе = права роли ∩ функции группы (`effectivePermissions` из `@btx24/shared`).
  `calendar.view` и `group.manage` не выключаются функциями группы.
- Участник — сотрудник (`USER`) или отдел (`DEPARTMENT`) **вместе с вложенными**: отделы
  сотрудника дополняются всеми вышестоящими по `department.get` (кэш 10 мин на портал). Нет
  scope `department` — только прямые отделы (`UF_DEPARTMENT`), в журнал — предупреждение.
- Роль, назначенная сотруднику **лично**, важнее ролей его отделов (в обе стороны: можно и
  повысить, и понизить). Несколько отделов — старшая роль (`ROLE_RANK`).
- Администраторы приложения = администраторы портала (`user.admin`, всегда) + список `AppAdmin`.
  Видят все группы как `APP_ADMIN`.
- Решение о доступе — только здесь. Контроллеры: `access.resolve(user)` → `access.pick(…, permission)`;
  админские эндпоинты — `@UseGuards(B24AuthGuard, AppAdminGuard)`.
- Группа сужает, но не расширяет права CRM: запросы к Битрикс24 — токеном пользователя.
