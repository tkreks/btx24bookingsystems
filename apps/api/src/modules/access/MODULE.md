# access

**Назначение:** кто что может — группы пользователя, роль, права (ADR 0005). `GET /api/session`
(в т.ч. `canManageApp`).

**Инварианты**
- Право в группе = права роли ∩ функции группы (`effectivePermissions` из `@btx24/shared`).
  `calendar.view` и `group.manage` не выключаются функциями группы.
- Участник — сотрудник (`USER`) или отдел (`DEPARTMENT`) **вместе с вложенными**: отделы
  сотрудника дополняются всеми вышестоящими по `department.get` (кэш 10 мин на портал). Нет
  scope `department` — только прямые отделы (`UF_DEPARTMENT`), в журнал — предупреждение.
- Роль, назначенная сотруднику **лично**, важнее ролей его отделов (в обе стороны: можно и
  повысить, и понизить). Несколько отделов — старшая роль (`ROLE_RANK`).
- Администраторы приложения = администраторы портала (`user.admin`, всегда) + список `AppAdmin`.
  Видят все группы как `APP_ADMIN`.
- Решение о доступе — только здесь. Контроллеры: `access.resolve(user)` → `access.pick(…, permission)`;
  админские эндпоинты — `@UseGuards(B24AuthGuard, AppAdminGuard)`.
- Группа сужает, но не расширяет права CRM: запросы к Битрикс24 — токеном пользователя.

## Временный доступ к настройкам (решение владельца 2026-10-21)
Кнопка «Настройки» — только на дашборде. Открыть её могут администраторы приложения или
сотрудник с **временным паролем**: постоянный администратор создаёт одноразовый пароль на
1–72 часа (`POST /api/admin/settings-codes`, в БД — только sha256(portalId:код)), сотрудник
вводит его (`POST /api/settings-access`) и до `expiresAt` считается администратором приложения
(`UserAccess.tempAdminUntil`, `SessionInfo.settingsAccessUntil`). Отзыв прекращает доступ сразу.
Выдавать пароли и менять список администраторов / сбор данных (`PUT /api/admin/settings`) может
только постоянный администратор (`PermanentAdminGuard`). 5 неверных вводов — пауза 15 минут
(счётчик в памяти api).

## Доступ к приложению (решение владельца 2026-10-22)
Открыть приложение могут только администраторы (портала, из `AppAdmin`, по временному паролю) и
сотрудники из списка `AppUser` (⚙ → «Приложение» → «Доступ к приложению»; отдел — с вложенными).
Членство в группе доступа к приложению **не даёт**. Проверка — глобальный перехватчик
`AppAccessInterceptor` (после `B24AuthGuard`): любой маршрут с сотрудником без доступа → 403
`APP_ACCESS_DENIED`. Исключение — `GET /api/session` (`@OpenWithoutAppAccess`): отдаёт
`appAccess: false`, интерфейс показывает «Доступ к приложению ограничен»; сторож сессии блокирует
открытое приложение, если сотрудника убрали из списка. Маршруты без сотрудника (установка, события
Битрикс24) не затрагиваются. Список меняет только постоянный администратор (`PUT /api/admin/settings`,
поле `appUsers`; нет поля — список не меняется).
