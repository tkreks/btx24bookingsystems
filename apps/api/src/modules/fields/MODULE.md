# fields

Назначение: ⚙ → «Поля», группы «Бронирование», «Визит», «Оплаты», «Контакт и мессенджеры».
Реестр ролей и совместимости — `@btx24/shared/system-fields`.

- `GET /api/admin/fields` — B24AuthGuard + AppAdminGuard, справочники полей сделки/контакта
  токеном сотрудника, сохранённые и фактические сопоставления текущего портала.
- `PUT /api/admin/fields` — дополнительно PermanentAdminGuard. Сохраняет обе карты атомарно
  в PortalSettings (`dealFieldMap`, `contactFieldMap`). Поле должно существовать, быть пользовательским,
  изменяемым, совместимым по типу и кратности; один код не назначается двум ролям одной сущности.
  Прежние неизменённые связи сохраняются и при изменении типа CRM; показываются с предупреждением/текстом.
- `POST /api/admin/fields/:entity/:key/create` — PermanentAdminGuard, явная кнопка.
  Сначала ищет совместимое поле по собственному коду/названию, при отсутствии создаёт новое UF-поле.
  Повтор использует прежнее поле; чужие поля не меняются и не становятся «системными».
- Сохранение/создание связи не переносит и не меняет значения карточек. Контакты пока только
  читаются (решение владельца 2026-10-28). Новые поля контакта остаются пустыми, пока их не
  заполнят в Битрикс24. Локальные связи MessengerChat и прежние данные не удаляются.
- Сопоставления и создание поля — в ActionLog от имени сотрудника; данные контактов и их
  наблюдаемая история — crm-mirror. Все настройки и данные изолированы по порталу.
- Поля отображаются с названиями, типами и вариантами списков CRM. В данных карточек даты,
  деньги, списки и логические значения форматируются, неизвестные составные значения выводятся текстом.

## Компактный каталог и обнаружение существующих полей (2026-10-28)
В интерфейсе раздельны «Поля приложения» (роли) и «Все поля Битрикс24» (полный справочник
стандартных/пользовательских полей сделки и контакта). Есть поиск и фильтр сущности.
Сопоставления — в той же компактной строке, combobox с 8 подсказками по названию/коду,
клавиатурой и объяснением несовместимости; сам ввод не меняет связь до выбора варианта/сохранения.

`resolved.contact` содержит только **существующие совместимые** поля: собственный код — первым,
затем известные поля Wazzup. `mappings` — сохранённая карта, «Найдено» отличается от «Сопоставлено».
Собственный Telegram ID может уже существовать без сохранённой карты. WhatsappLid_WZ — одиночный
цифровой ID, отдельная роль whatsappLid; его не подставляем в множественные адреса WhatsApp.
Добавлены роли логинов Telegram/MAX. Пустое отсутствующее поле не выдаётся за созданное.

`systemUserIds` в PUT (до50 положительных ID) сохраняется в contactSystemUserIds, журналируется
вместе с картами. Эта настройка классифицирует аккаунт, не даёт права писать контакты.
