# certificates

**Назначение:** подарочные сертификаты портала (решение владельца 2026-10-23). У сертификата — номер,
номинал, на чьё имя, статус (`new` — новый, `used` — использован, `expired` — истёк), дата оплаты,
срок действия («действителен до», включительно), необязательная сделка и комментарий.
Маршруты (`B24AuthGuard`): `GET /api/certificates?status=&q=` (список, счётчики, `canManage`),
`GET /api/certificates/:id` (карточка с историей), `POST /api/certificates` (выпуск),
`PUT /api/certificates/:id` (изменение срока), `POST /api/certificates/:id/redeem` (погашение).
Интерфейс — 🎟 «Сертификаты» на дашборде (`web/src/certificates/CertificatesPage.tsx`).

**Инварианты**
- Тенант — портал из контекста; чужой сертификат — 404, как несуществующий.
- Смотрят все с доступом к приложению; **выпускают, меняют и погашают** — администраторы
  приложения и сотрудники с правом `payment.send` хотя бы в одной группе (`canManage`). Проверка — в
  сервисе, а не в интерфейсе.
- Номер уникален в портале (`@@unique([portalId, number])`), хранится в верхнем регистре. Пусто при
  выпуске — следующий: наибольший чисто цифровой + 1, шесть знаков («000124»); гонку решает unique
  (повтор до 3 раз). Занятый введённый номер — 409 `NUMBER_TAKEN`.
- Даты (`paidOn`, `validUntil`) — колонка `DATE`, дни портала без времени (полночь UTC в Prisma).
  Срок не раньше даты оплаты. Номинал > 0 (CHECK в БД).
- Изменение — только срока и только у нового. Погашение — причина `used`/`expired` = итоговый статус,
  один раз: условие `status = new` внутри `updateMany` (параллельное погашение не пройдёт дважды,
  изменение срока не «оживит» погашенный). Удаления нет.
- Каждое действие — `CertificateEvent` (история карточки, было → стало) и журнал действий
  (`certificate.issued|changed|redeemed`).
- Новый сертификат с прошедшим сроком сам статус не меняет: в списке он «срок прошёл» (`overdue`,
  фильтр `status=overdue`), сотрудник гасит его как «истёк».

**Продажа из мастера брони** — `POST /api/certificates/sale` (см. bookings/MODULE.md): ключ
`idempotencyKey` → `saleKey` (повтор не выпускает второй сертификат); вид — бумажный / электронный (`kind`);
дата оплаты пустая до оплаты.

**Пока нет:** связи с оплатой брони (списание номинала в сделке), печатной формы, автопогашения по сроку.
