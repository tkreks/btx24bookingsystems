# calendar

**Назначение:** календарь броней на день — только чтение. `GET /api/calendar?date=YYYY-MM-DD`
→ `CalendarDay` из `@btx24/shared` (ресурсы, брони, связанные сделки, поля сделки, тех. окна).

**Инварианты**
- Источник данных — модуль бронирования Битрикс24 (ADR 0003); своих копий броней не храним.
  Исключение — **бронь приложения или бронь по сделке, удалённая в Битрикс24** (решение владельца
  2026-10-23): активная запись журнала дня (`source = app` или есть `dealId`), которой нет в списке, проверяется `booking.v1.booking.get`
  пакетом; достоверно «not found» → бронь в ответе с `missing: { alertId }` (без тех. окна — слот в
  Битрикс24 свободен), пока сотрудник не решит: «Оставить бронь» (создать заново) или «Удалить из приложения»
  (`bookings/booking-restore.service.ts`). Сбой проверки — бронь пропавшей не считается.
- Все запросы — **токеном пользователя** (`B24AuthGuard`): сделки, недоступные ему в CRM,
  приходят как `deal: null` при известном `dealId`. Не подменять клиентом приложения — это
  раскрыло бы чужие сделки.
- «День» — сутки в часовом поясе портала (`Portal.timezone`), `[start, end)` через
  `zonedDayRange`; в ответе время в UTC (ISO), пояс — в поле `timezone`.
- `booking.v1.booking.list` отдаёт ≤50 записей без пагинации: при 50 отрезок делится пополам
  (до 15 минут), результаты склеиваются по `id`.
- Связь бронь → сделка — `booking.v1.booking.externalData.list` (`moduleId=crm`,
  `entityTypeId=DEAL`), пакетом.
- **Тех. окна** считаются, а не хранятся: `[конец брони, конец + techWindowMinutes группы)` на
  каждый ресурс брони (`techWindowsFor` в `@btx24/shared`). Окно, целиком перекрытое следующей
  бронью ресурса, не возвращается. Брони запрашиваются с запасом `techWindowMinutes` до начала
  дня — окно вчерашней поздней брони заходит в сегодня. Окно только предупреждает.
- **Поля сделки** — из `options.dealFields` группы (флаги «П» — карточка, «О» — список и
  календарь). В `crm.deal.list` добавляются только эти поля; подписи и варианты списков — из
  `crm.deal.fields` (кэш на портал, 10 минут); значения форматируются на сервере
  (`deal-fields.ts`). Без права `booking.details` полей нет.

**Пока нет** (следующие задачи): создание/изменение броней (запрещено режимом только чтения),
кэш на стороне worker.

## Свежесть данных (2026-10-24)

Ответы календаря и метаданные полей CalendarService не кэшируются. Веб-клиент
перечитывает вид календаря/списка/доступности и занятость мастера каждые 15 секунд,
при возврате на вкладку и после действий. HTTP — no-store. Подробнее: [синхронизация](../../../../../docs/features/dashboard-sync.md).
