## Режим работы с порталом
- `B24_READ_ONLY=true`: любые изменения в Битрикс24 блокируются клиентом до запроса.
- **Песочница** (решение владельца): тестовая сделка **678** (контакт 140 — сам владелец) —
  изменения можно, удаление нельзя; её контакт, смарт-счета и оплаты — можно; брони — только с
  датами в **2020** году, потом удалять. Уборка броней:
  `docker compose exec -T -w /repo/apps/api api node dist/scripts/sandbox-cleanup.js --member <member_id> [--apply]`.
- **Создавать новые** (решение владельца 2026-10-22): брони на любые даты и новые сделки —
  переключатель ⚙ → «Приложение» → «Запись в Битрикс24» (`PortalSettings.createInBitrix`).
  Менять можно только созданное приложением (`AppCreatedEntity`); существующие сделки не меняются —
  бронь к ним создаётся, а поля и товары сделки не пишутся (предупреждение в форме).
  Счета и ссылки на оплату — ADR 0009 (`modules/payments`), поля сделок — переключатель
  «Менять поля существующих сделок» (`updateDealFields`, решение владельца 2026-10-22).
- Интерфейс: токен Битрикс24 обновляется заранее (`web/src/b24.ts`), сторож сессии
  (`session-guard.ts`) раз в 5 минут проверяет вход и версию и блокирует экран «Обновите страницу».
- Расширять разрешения — только по явному слову владельца.

### Создание из звонка: видимая обратная связь и товары (2026-10-24)

onSubmit. Ограничения времени, прав и обязательных полей сохраняются. Повтор отправки использует

вводом. Ноль убирает товар. Изменение суммарного количества дублирующихся строк существующей
сделки сохраняет цены/скидки: рост первой строки, уменьшение с последних строк. Количество
