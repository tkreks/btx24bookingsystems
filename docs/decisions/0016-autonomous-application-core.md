# ADR 0016: собственное ядро и внешние адаптеры

Дата: 2026-10-24. Статус: направление задано владельцем; реализация запланирована, не выполнена.

## Основание

Владелец: всё приложение должно работать на собственных данных и БД; Битрикс24 и мессенджеры
передают события, данные сверяются автоматически и по инициативе сотрудников. Приоритеты —
надёжность, защищённость и скорость. Битрикс24 остаётся основной внешней CRM-интеграцией.
Сейчас требуется только план. Создавать БД и переключать рабочие подключения пока не разрешено.

## Решение для последующей реализации

1. Собственные tenant/клиенты/переписки/брони/правила и внутренние ID. Внешние ID хранятся
   как соответствия с историей происхождения. Отключение портала не удаляет собственные данные.
2. Локальное чтение и собственные права/вход. Синхронизация через устойчивые inbox/outbox,
   фоновые адаптеры, события и сверки. Подтверждение события только после постоянного сохранения.
3. Начать с одной основной транзакционной MariaDB для связанных данных и очередей;
   файлы — в собственном закрытом хранилище. Статистика — пересчитываемые проекции, отдельный
   экземпляр хранения при измеренной необходимости. Число БД не является мерой надёжности.
4. Внешние факты сохраняют происхождение: доставка подтверждается транспортом, оплата —
   платёжной системой/разрешённой операцией, внешние права — выбранной политикой интеграции.
   Неопределённый результат не заменяется вымышленным успехом или слепым повтором.
5. Поэтапная миграция владения каждым доменом/ресурсом. При переносе бронирования локальная
   транзакция становится окончательной защитой интервалов; несколько независимых внешних
   писателей при разрыве связи требуют отдельного ограничения/режима подтверждения.
6. Для Wazzup сохранять историю и связи в ядре; старый и новый внешние диалоги могут указывать
   на одну внутреннюю переписку. Сохранение LINE_ID не гарантирует прежний штатный CHAT_ID.
7. Один разрешённый исходящий маршрут на аккаунт, управляемая граница переключения, архив
   и проверяемый откат без удаления новых данных. Не использовать подмену чужого коннектора.

## Переход и последствия

Направление заменяет ограничения ADR0003/0007/0013 о внешнем источнике истины/копии-кэше
по мере реализации и приёмки конкретного домена. Оно уточняет ADR0014/0015 о связях каналов
и маршруте отправки. До переключения действуют прежние механизмы фактического кода.
При реализации обновить AGENTS.md, инварианты модулей, контракты, миграции и тесты вместе.
Нельзя просто объявить нынешний кэш основной БД или ослабить проверки прав.

Потребуются постоянные очереди, собственная полная история/медиа, модель внешних соответствий,
устранение синхронных зависимостей чтения от Битрикс24, политика конфликтов/прав и испытания
восстановления. Поддержка внешних мессенджеров сохраняет ограничения соответствующих транспортов.
