# 0001. Стек и база данных

- Статус: частично заменено ADR 0004 (СУБД и контейнеры)
- Дата: 2026-10-20

## Контекст
Новое приложение Битрикс24 с системой бронирования. Команда уже ведёт проект ratingsystem на
TypeScript/NestJS/Prisma/React с агентным процессом разработки — опыт и инструменты хочется
переиспользовать.

## Решение
- Монорепозиторий npm workspaces: `apps/api` (NestJS 12, Prisma 7), `apps/web` (React 19,
  Vite 8), `packages/shared`, `tools/mcp-server`. Node 24, ESM, TypeScript 6.
- **PostgreSQL 18**, а не MariaDB/MySQL: ключевой инвариант бронирования — отсутствие
  пересечений интервалов для одного ресурса — выражается декларативно ограничением
  `EXCLUDE USING gist (resource_id WITH =, tstzrange(starts_at, ends_at, '[)') WITH &&)`
  (расширение `btree_gist`). В MySQL это пришлось бы обеспечивать блокировками в коде.
  Плюс `timestamptz`, range-типы, частичные индексы, `jsonb` для настроек.
  *Уточнено ADR 0003:* брони хранит Битрикс24, поэтому EXCLUDE для них не нужен; выбор
  PostgreSQL остаётся в силе по остальным причинам.
- Один контейнер приложения: api раздаёт собранный web (`WEB_DIST_DIR`) — у приложения
  Битрикс24 один публичный адрес-обработчик.
- Prisma Client генерируется в `apps/api/src/generated/prisma` (генератор `prisma-client`
  выдаёт TS-исходники, им нужно лежать внутри `rootDir` сборки).

## Последствия
- То, что Prisma не описывает (EXCLUDE, CHECK), пишется SQL в миграциях и документируется.
- Линтер — oxlint (как в шаблоне NestJS 12), тесты — vitest во всех workspace'ах.
