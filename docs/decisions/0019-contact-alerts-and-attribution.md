# ADR 0019: предупреждения контактов и достоверная атрибуция

Дата: 2026-10-28. Статус: принято по запросу владельца.

## Контекст
Входящие контактные данные уже сохраняются вместе с историей. Требуются заметные отклонения/
удаления, удобные сопоставления и различение сотрудника, системного аккаунта и приложения.
Редактирование контактов остаётся запрещённым.

## Решение
- ContactAlert — отдельная таблица с portalId, уникальным отпечатком, статусом и состоянием
  доставки. Создаётся атомарно с историей/снимком. Не смешиваем контакт с BookingAlert.bookingId.
- Первичная загрузка — история без предупреждений. Изменение известного бизнес-поля после
  подтверждённого события/роста DATE_MODIFY — отклонение; служебные даты/флаги не сигнализируют.
- ONCRMCONTACTDELETE подтверждает удаление. Отсутствие в периодическом списке известных ID
  означает лишь недоступность: может быть удаление или изменение прав. Копия сохраняется.
- Уведомления появляются на общей странице, в счётчике дашборда и в ранее выбранном чате.
  В общий чат не отправляем значения контактных полей. Детали API требуют CRM-видимости.
- MODIFY_BY_ID — последний редактор, не доказательство автора каждого промежуточного действия.
  Для удаления без источника автора показываем неизвестного; комментарии таймлайна не используем
  для догадок. Общего history-read REST живой портал не предоставляет.
- Настройка contactSystemUserIds определяет тип аккаунта, а не приложение-инициатор.
  Источник наблюдения и аккаунт хранятся отдельно, application остаётся null без корреляции.
  Известные собственные действия приложения имеют automation, operationId и аккаунт исполнения.
- Роли приложения и полный справочник CRM показываются раздельно, поиск — по названию/коду.
  Найденные реальные поля отличаются от сохранённых сопоставлений. Существующие Wazzup-поля
  допускаются по типу; WhatsApp LID не смешивается с множественными адресами WhatsApp.

## Последствия
Не теряем копию при недоступности контакта, не приписываем автоматизацию человеку или обратно.
Блокировка REST-записи контактов сохраняется. Повтор события не создаёт дубль предупреждения;
неоднозначный сетевой исход отправки в чат может дублировать доставку, как у броней.
Начальные снимки не восстанавливают исторические действия до наблюдения.
