# ADR 0017: переписка = клиент × наш канал

Статус: принято, 2026-10-27 (решения владельца). Уточняет ADR 0015 и 0013 для чатов.

## Контекст
В Битрикс24 у одного клиента много чатов открытых линий: прежний провайдер (Wazzup) и наш
коннектор на том же номере, отдельные линии под номер, повторные диалоги, чаты «под сделку»
(`<чат>::deal:<id>`, ADR 0015). У контакта 140 их было 7, а по сути каналов 3. Владелец: в «Чатах» у
клиента столько чатов, сколько у него мессенджеров с нашими номерами (TG, WhatsApp (1), WhatsApp (2)),
и в каждом — вся история. Приложение должно работать максимально быстро: всё полученное из
Битрикс24 хранится в БД приложения.

## Решение
1. **Переписка** — ключ `<наш канал>|<клиент>` (`OpenlineChat.convKey`):
   - наш канал — по линии чата (`ChatLineChannel`): `<вид>:<наш номер>` или `line:<id>`. Канал линии
     подбирается сам (линия своего номера; цифры нашего номера в названии линии), администратор
     меняет его в ⚙ → «Мессенджеры» → «Каналы линий»;
   - клиент — контакт CRM, затем компания, лид; без CRM — собеседник линии (внешний чат из `entity_id`,
     `::deal:<id>` отрезается). Группа мессенджера (`…@g.us`) — всегда своя переписка.
   Разные наши номера — разные переписки; Wazzup и наш коннектор на одном номере — одна.
2. **Сделка — метка сообщения**, а не чат: новые диалоги ОЛ под сделку не создаются
   (`MessengerConnectorService.relayTarget`), прежние `::deal:` чаты вливаются в переписку.
3. **История в БД** (`OpenlineMessage`, при «сборе текстов»): worker сохраняет последние сообщения
   индексируемых чатов, лента дочитывает старую историю из Битрикс24 при первом открытии.
   Хранимое — непрерывный диапазон ID `[msgFromId, msgToId]` у чата (ID сообщений растут по порталу),
   поэтому ленту нескольких чатов склеиваем по ID без отдельной пагинации по каждому.
4. **Права — токеном сотрудника** (выбор владельца): переписку видит тот, кому Битрикс24 открывает хоть
   один её чат; в ленту попадают только такие чаты (`OpenlineChatAccess`, перепроверка ≤ 5 минут),
   остальные — строкой «скрыто N диалогов». Чтения токеном приложения для истории нет.
5. **Отправка** — в один чат переписки: последний чат своей линии приложения, иначе последний доступный
   (`sendChatId`); проверки рабочей линии (`chatLineProblem`) действуют как раньше.

## Последствия
- Списки (вкладки, папки, поиск, встройка сделки, «Ждут ответа», «Чаты клиента») — по строке на
  переписку; строка — сводка последнего чата, непрочитанные суммируются, папка/★/«!» — с любого чата.
- Действия по-прежнему адресуются чатам (`/openlines/chats/:chatId/*`): любой чат переписки открывает
  всю переписку. Отдельной таблицы переписок нет — ключ пересчитывает worker раз в минуту.
- Новые чаты до прохода worker'а — сами по себе (без ключа); изменения и удаления старых сообщений,
  ушедших из последних 20 / 50, в копии не обновляются.
