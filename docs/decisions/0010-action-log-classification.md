# ADR 0010: классификация неизменяемого журнала при чтении

Статус: принято. Дата:2026-10-24.

## Контекст
Владелец запросил до10категорий событий и критичность во всём журнале. ActionLog только
пополняется: UPDATE/DELETE запрещены триггерами. Уже есть исторические события многих модулей,
включая общий request и вложенные изменения доступа в группе/настройках.

## Решение
Общий чистый classifier в shared определяет category/severity из action и структурированных
details при чтении; API возвращает поля, UI показывает и фильтрует. Старые записи работают
без backfill и изменения аудиторских данных. Новые события используют тот же classifier.
Правила не зависят от человеческого текста. Категорий10, уровней4; неизвестный код — Прочее.
Для server-side фильтрации читаются последовательные страницы в пределах portal/period/query
до limit+1 совпадений. Пагинация по at/id сохраняет все совпадения и порядок. Без этих фильтров
остаётся limit+1 запрос. Права и tenant-фильтры не меняются.

## Последствия
Классификация применяется ко всей истории сразу; корректировка правил переосмысляет категории,
не меняя исходные записи. Фильтр редкой категории может потребовать несколько чтений БД;
страницы ограничены200, дальнейшие запросы продолжаются по показанному курсору. Если объём
существенно вырастет, индексированная производная проекция может быть добавлена отдельно,
с сохранением исходного append-only журнала. Изменять триггеры или старые записи запрещено.
