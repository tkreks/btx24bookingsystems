# 0002. MCP-сервер для агентов

- Статус: принято
- Дата: 2026-10-20

## Контекст
Разработка ведётся в основном AI-агентами. В ratingsystem локальный read-only context-server
сократил «чтение всего репозитория» и повторные поиски. Здесь проект с нуля, поэтому сервер
можно заложить сразу и шире: агентам нужна не только навигация по коду, но и состояние стенда
(контейнеры, логи, фактическая схема БД, данные).

## Решение
Один stdio MCP-сервер `btx-dev` (`tools/mcp-server`, Node ESM, официальный
`@modelcontextprotocol/sdk`) с двумя группами инструментов:
1. Репозиторий: `project_overview`, `search_code`, `read_source`, `get_module_context`,
   `get_task_state`.
2. Стенд, только чтение: `env_status`, `app_logs`, `db_schema`, `db_query`.

Один реестр инструментов обслуживает MCP и CLI. Записи нет ни в одном инструменте; доступ к БД —
отдельной ролью `agent_ro`. Подробности — `docs/agents/MCP_SERVER.md`.

## Альтернативы
- Скопировать context-server из ratingsystem целиком — избыточен для пустого репозитория
  (TS Compiler API, бенчмарки), не умеет runtime-диагностику.
- Готовые postgres/docker MCP-серверы — шире по правам (запись, произвольные команды), без
  маскирования секретов и без знания структуры проекта.

## Последствия
- Индекс лексический; при росте кода — добавить `find_references` через TS Compiler API.
- Агенту, работающему с `env_status`/`app_logs`, нужен доступ к Docker.
