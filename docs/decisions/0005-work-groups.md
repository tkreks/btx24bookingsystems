# 0005. Группы: направление + люди + права

- Статус: принято (решения владельца 2026-10-21)
- Дата: 2026-10-21

## Контекст
В прототипе «группа» — это группа ресурсов (бани, домики) с воронкой, режимом времени, оплатами
и полями сделки. Владелец хочет, чтобы в группе задавались ещё и люди, их функционал и права:
с какими канбанами, шаблонами и действиями они работают. Ответы владельца: группа ресурсов и
группа людей — **одно целое**; участники — **и сотрудники поимённо, и отделы**; сбор данных
диалогов — **переключатель в настройках приложения**.

## Решение
1. **Группа (`WorkGroup`)** = рабочее направление портала:
   - воронка сделок (`dealCategoryId`) и ресурсы бронирования (`WorkGroupResource`);
   - режим времени (`duration` / `interval`), тех. окно и прочие настройки направления;
   - **участники** (`WorkGroupMember`): сотрудник Битрикс24 (`USER`) или отдел (`DEPARTMENT`,
     включая вложенные), у каждого роль;
   - **функции группы** (`features`): какие действия вообще включены в этом направлении.
2. **Роли** — фиксированный набор в коде (`@btx24/shared`, `ROLE_PERMISSIONS`):
   `VIEWER`, `TECHNOLOGIST`, `MANAGER`, `GROUP_ADMIN`. Право пользователя в группе =
   права роли ∩ функции группы. Роль, назначенная сотруднику лично, важнее ролей его отделов
   (уточнение владельца 2026-10-21: выбор должен быть гибким); среди отделов — старшая роль.
3. **Администраторы приложения** (`AppAdmin`, сотрудники или отделы) и администраторы
   портала Битрикс24 управляют всеми группами и настройками. Администратор портала — всегда,
   чтобы не потерять доступ.
4. **Права CRM не расширяются:** все чтения/записи идут токеном пользователя; группа только
   сужает видимое (ресурсы, воронка) и разрешённые действия.
5. **Настройки портала (`PortalSettings`):** переключатели сбора данных диалогов —
   метаданные (время последнего сообщения клиента/оператора) и тексты сообщений — по
   умолчанию **выключены**; включает администратор приложения в интерфейсе.
6. Проверка прав — только на сервере (`AccessService`), интерфейс лишь скрывает недоступное.

## Последствия
- Календарь показывает ресурсы групп пользователя; без групп — ничего (кроме администраторов).
- Для отделов с вложенными подразделениями нужен scope `department` (`department.get`); без
  него учитываются только прямые отделы сотрудника (`UF_DEPARTMENT`).
- Шаблоны сообщений, оплаты, поля сделки — следующими шагами, внутри той же группы.
