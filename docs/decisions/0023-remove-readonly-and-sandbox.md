# ADR 0023: режим «только чтение» и песочница записи убраны

Статус: принято, 2026-10-31 (решение владельца).

## Контекст
Режим `B24_READ_ONLY` и песочница записи (`B24_SANDBOX_*`, `SandboxWritePolicy`, журналы `SandboxBooking` и
`AppCreatedEntity`, переключатели «Создавать новые…» и «Менять поля сделок») появились в начале разработки, чтобы
сбой не испортил данные боевого портала. Теперь приложение работает с боевыми данными полноценно; на стенде
`B24_READ_ONLY=false`, песочница не действовала.

## Решение
1. Удалены: `SandboxWritePolicy` и его настройки, `B24_READ_ONLY`, `B24_SANDBOX_*` (env, compose, `.env.example`),
   скрипт `sandbox-cleanup`, `WritePolicy` и `readOnly` в REST-клиенте, `session.readOnly` и плашка «Режим просмотра»,
   два переключателя в ⚙ → «Приложение» (`createInBitrix`, `updateDealFields`).
2. Остаётся запрет правки контактов (`assertContactsReadOnly`, исключение — объединение дублей, ADR 0022): это отдельное
   решение владельца 2026-10-28.
3. Для совместимости оставлены таблицы `SandboxBooking`, `AppCreatedEntity` и колонки `PortalSettings.createInBitrix`,
   `createGrantedByUserId`, `createGrantedAt`, `updateDealFields` — приложение их не читает (кроме записи `AppCreatedEntity`
   при выставлении счёта); удалить можно отдельной миграцией.
4. «Свой» счёт для аннулирования ссылки на оплату определяется заявкой `PaymentRequest.invoiceId` (журнал — запасной вариант).

## Последствия
Защиты «приложение меняет только созданное им» больше нет — права действий задают `AccessService` (ADR 0005) и токен
сотрудника в Битрикс24. Обработчики `READ_ONLY_MODE` в сервисах остались как безвредный запас.
