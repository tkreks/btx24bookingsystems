# ADR 0015: контекст сделки и канала клиента

Статус: принято, 2026-10-24. Основание: выбор сделки и канала выполняет сотрудник.

## Контекст
Один клиент может иметь несколько активных сделок и общаться через несколько каналов.
Номер приходит в разных форматах, WhatsApp может заменить адрес по номеру скрытым LID.

## Решение
Нормализуем RU +7/7/8/10 цифр; CRM ищем через Bitrix24. В HTTP кандидаты определяются правами
сотрудника. Выбор activeDealId хранится на клиенте номера; каждое сообщение получает снимок
сделки. Меняются только ожидающие выбора сообщения, история не переезжает. Завершённая сделка
пригодна для просмотра, новые сообщения требуют активной. Импорт истории не получает текущую сделку.

При первом входящем к известной сделке не открываем новый канал ОЛ автоматически. Менеджер
может продолжить доступный существующий диалог либо явно выбрать собственный канал в приложении.
Выбор/применение сделки передаёт ожидающие входящие в свою ОЛ, клиенту ничего не отправляется.
Следующая сделка получает virtual chat ID; при доставке в мессенджер убираем суффикс. Для правок
и удаления сохраняем исходный relayChatId. Чужие провайдеры остаются отдельными подключениями.

## Последствия
Новые метаданные — миграция00900, без дублирования CRM как источника истины. Список и контекст
доступны по группам/read/send; связанные ОЛ дополнительно проверяются user.client. Новые действия
сотрудника передают ожидаемую сделку, чтобы переключение другим сотрудником обнаруживалось409.
Режим истории фильтруется сервером до пагинации. Данные броней/календаря и их кэш не меняются.
