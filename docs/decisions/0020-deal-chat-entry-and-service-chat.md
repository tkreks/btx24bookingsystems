# ADR 0020: вход в чат из сделки, служебный чат, привязка чата

Статус: принято, 2026-10-29 (требования владельца). Уточняет ADR 0017 (переписка = клиент × наш канал).

## Контекст
Во встройке сделки у многих клиентов только «протухшие» чаты Wazzup (канал линии не подключён):
менеджер видел баннер «Нет рабочего чата…» и должен был сам выбирать, где продолжить. У новых
клиентов чатов нет вовсе, и ссылкам на оплату некуда было падать. Владелец: упростить вход в такие
чаты; служебный чат для клиентов без мессенджеров; возможность привязать чат из мессенджера.

## Решение
1. **Линия ↔ один аккаунт мессенджера.** Канал линии (`ChatLineChannel.channel` = `<вид>:<наш номер>`,
   ⚙ → «Мессенджеры» → «Каналы линий») — это и есть закрепление: чат прежнего провайдера на этой линии
   продолжается только через этот наш номер. Не сопоставлена (`line:<id>`) — выбор из всех номеров.
2. **Встройка сделки без баннера.** Чат один — открыт сразу (даже неработающий). В неработающем чате
   вместо поля ввода — «Присоединиться к чату»: `GET /messengers/chat-targets/:chatId` находит клиента
   (контакт чата, иначе контакт его сделки) в номере канала; найден в одном номере — сразу первое
   сообщение (`POST /messengers/:id/send {forDeal}`), диалог линии свяжется с контактом сделки.
   В шапке открытого чата — «Другой мессенджер» и «Привязать чат».
3. **Чатов нет** — сразу «Ищем клиента в мессенджерах…» (`deal-targets`): мессенджер → номер (если
   несколько) → написать/открыть. «✕ Без мессенджера» — служебный чат сделки.
4. **Служебный чат** (`ServiceChat`, `ServiceChatMessage`): одна строка на сделку, только в приложении —
   в Битрикс24 не отправляется. Автоматика (`PaymentFlow.sendToClient`/`sendChain`) пишет туда, когда у
   сделки нет рабочего чата и сотрудник не выбрал мессенджер; файлы — строкой «Файл для клиента».
   Окно оплаты при служебном чате не требует выбрать мессенджер. Сотрудники оставляют заметки.
   Видит тот, кому Битрикс24 открывает сделку; читать — `openlines.read`, писать — `openlines.send`.
5. **Привязать чат**: мессенджер → номер → последние 10 чатов номера, «Загрузить ещё», поиск по всем
   чатам номера (`GET /messengers/:id/bind-chats`). `POST /messengers/:id/chats/:chatId/bind {dealId}`
   связывает чат с контактом сделки в приложении (`MessengerChat.crmContactId`, контакт CRM не
   меняется). Чат уже у другого контакта (в приложении или его диалог линии) — не привязываем:
   диалог линии REST к другому контакту не перепривязать, менеджеру — «объедините контакты».
   У клиента другие сделки в работе — привязываем и подсказываем объединить сделки.
6. **Шкала броней** во встройке открывается на дне брони сделки (текущая/будущая, иначе последняя) и
   прокручивается к ней; брони этой сделки выделены.

## Последствия
- Служебный чат — новые таблицы; это не «своя копия» переписки Битрикс24, а сообщения, которых в
  Битрикс24 нет по смыслу (ADR 0003 не нарушается).
- Клиенту по-прежнему ничего не уходит без явного действия сотрудника.
