# Классификация журнала действий

Каждая запись получает одну категорию и критичность независимо от автора и источника.
Правило единое — `packages/shared/src/audit-classification.ts`, по коду действия,
маршруту запроса, изменённым полям и структурированному результату. Описание для человека
не используется для угадывания категории. Старые записи классифицируются тем же правилом.

| Категория | Примеры |
|---|---|
| Безопасность | вход, отказ в доступе, участники/права/доступные ресурсы/функции группы, архивирование группы, администраторы, доступ к приложению, пароли, глобальность папки |
| Настройки | обычные настройки, правки группы без изменения доступа, шаблоны, личный дашборд |
| Бронирования | создание/отмена/импорт/сверка, решения по уведомлениям, восстановление |
| Сделки и клиенты | открытие редактирования и изменение полей сделки |
| Оплаты и сертификаты | счета/ссылки, оплата, истечение срока, выпуск/изменение/погашение сертификата |
| Сообщения и чаты | сообщения, файлы, папки, избранное, присоединение, статус ответа |
| Ресурсы | стопы/снятие стопов, название ресурса для клиента |
| Интеграция | встройки, подписки, системные поля и настройки сверки |
| Ошибки | сбой интерфейса, REST Битрикс24, неуспешный запрос, неудавшийся откат |
| Прочее | рабочий день и будущие действия без специального правила |

Ошибка имеет приоритет над доменной категорией. Изменение доступа имеет приоритет
над обычными настройками, даже если одним запросом поменяли и название, и участников.
Предоплата без отправленной ссылки — «Оплаты и сертификаты», средняя критичность:
нужна ручная отправка, это не подтверждение доставки.

| Критичность | Когда |
|---|---|
| Низкая | штатное действие, успешный вход, обычное изменение/сообщение |
| Средняя | отмена/архивирование, расхождение брони, истечение оплаты, ссылка не отправлена, отказ в доступе, ожидаемый конфликт/валидация/лимит |
| Высокая | изменение участников/прав/администраторов/паролей; сбой HTTP портала или интерфейса, неизвестная ошибка запроса |
| Критическая | не удалось компенсировать создание брони: слот мог остаться занят после сбоя |

Проверены все обращения к ActionLogService и прямые записи ActionLog в исходниках: единственная
запись таблицы — ActionLogService.log. Дополнительно read-only сверены 25 накопленных кодов
действий и 17 маршрутов request действующего портала. Они покрыты правилами; рабочий день
намеренно относится к «Прочее». Событие legacy placements.sync также классифицируется.

Общий перехватчик не дублирует успешные подробно логируемые действия; теперь сохраняет их
ошибки, если запрос дошёл до обработчика. Для новых ошибок добавляется HTTP статус, позволяющий
отличить конфликт/валидацию/отказ от сбоя сервера. Убраны дубли activity/error и groups-order.
Ошибки предпросмотра шаблонов не включаются в журнал действий.

## Фильтрация и история

`GET /api/admin/action-log` принимает category/severity вместе с прежними фильтрами. Неизвестное
значение —400. Права администратора, portalId, диапазон дат зоны портала и состав деталей
сохраняются. Фильтры применяются до пагинации: сервер читает страницы по200 в пределах
выборки, пока не найдёт limit+1 подходящих записей либо конец. Курсор возвращается по последней
показанной подходящей записи, поэтому совпадения после промежуточных чужих категорий не теряются.
Без классификационного фильтра прежний быстрый запрос limit+1. UI начинает с5записей,
Показать ещё добавляет5; смена фильтра/периода сбрасывает список и отбрасывает запоздалые страницы.
Содержимое ActionLog не переписывается, триггеры неизменяемости не отключаются; миграция не нужна.
