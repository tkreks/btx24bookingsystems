# Конструктор брони в одном окне — спецификация (2026-10-26)

Заменил пошаговый мастер (`apps/web/src/bookings/BookingForm.tsx`). Макет —
`docs/prototype/ui/booking-constructor.html`. Статус: макет согласован владельцем 2026-10-26, реализовано
(этапы 1–6, кроме отложенного ниже).

**Отложено:** заголовки блоков полей сделки (нужна настройка поля в ⚙ — отдельной задачей); количество
почасового товара по длительности (в каталоге нет единицы измерения товара).

## Идея владельца
Чтобы создать бронь, нужно знать: **Кто, Когда, Ресурс, Длительность**. Затем — товары и допы, затем
поля сделки. Всё в одном окне, компактно. Заполненные разделы остаются видны свёрнутыми до одной
строки-сводки; в любой раздел можно вернуться и поменять; открыт ровно один раздел. В конце —
проверка сводки и подтверждение. Особое внимание: товары, окна каталога и доп. услуг, обязательные
поля, общий вид полей.

## Разделы
**К** Кто (клиент и сделка) · **Г** Группа (+ тип сделки) · **Р** Дата, ресурс и время ·
**С** Сертификат (только «Покупка сертификата») · **Т** Товары, допы и оплата · **П** Поля сделки ·
**✓** Проверка. Служебная бронь: вместо Т и П — «Комментарий».

## 1. Точки входа
Обозначения: ⬤ открыт первым; ✔ предзаполнен и свёрнут (можно поменять); 🔒 заполнен, не меняется; ○ ждёт.

| Вход | Известно | К | Г | Р | Т | П |
|---|---|---|---|---|---|---|
| Клик по свободному месту календаря/шкалы | дата, время, ресурс, группа | ⬤ | ✔ (тип «Визит») | ✔ | ○ | ○ |
| Календарь «+ Бронь» | дата, группа | ⬤ | ✔ при 1/активной группе | ○ | ○ | ○ |
| Встройка сделки «Мастер бронирования» | сделка, контакт | 🔒 | ⬤ (по воронке) | ○ | ○ | ○ |
| Шкала во встройке сделки (клик) | сделка + ресурс, время, группа | 🔒 | ✔ | ✔ | ⬤ | ○ |
| Чат, «+» в шапке | контакт, открытые сделки (из оплаты — сделка) | клиент 🔒; 0 сделок → ✔ «Новая»; ≥1 → ⬤ выбор; есть сделка → 🔒 | ○ | ○ | ○ | ○ |
| Звонок (карточка, CALL_CARD) | контакт, сделки, выбранная сделка | как чат; сделка выбрана, К открыт для подтверждения | ○ | ○ | ○ | ○ |
| Контакт | встройки пока нет | как чат | | | | |
| Меню, дашборд | дата (+группа) | ⬤ поиск, «Последняя активность» | ○ | ○ | ○ | ○ |

Правила: одна группа — в Г только дата и название группы текстом; служебная — без Т и П;
сертификат — вместо Р+Т+П раздел С, кнопка «Оформить сертификат»; окно «По сделке уже есть бронь»
остаётся до открытия, внутри — предупреждение у К и на проверке; первым открывается первый пустой раздел.

## 2. Зависимости и сбросы
Порядок `who → when → slot|certificate → goods → fields → review`; раздел доступен, если заполнены его
зависимости (slot ← группа+дата; goods ← группа (+сделка); fields ← группа+сделка). Заблокированный —
серая строка «Сначала выберите группу».

| Изменение | Последствия |
|---|---|
| Сделка A → B | поля перечитываются, «Оставить/Очистить» — заново; товары сделки B (если правили — уведомление); группа по воронке B — только если Г не трогали руками, иначе подсказка |
| существующая ↔ новая | товары сделки ↔ товары ресурсов по умолчанию; поля — сделки ↔ по умолчанию |
| → служебная | Т и П скрываются (данные сохраняются) |
| Группа | ресурсы не из группы снимаются; период пересчитывается; товары вне каталога удаляются (уведомление); тип брони сброшен; оплата — первый разрешённый режим; поля перечитываются |
| Дата | ресурсы и время сохраняются; занятость перепроверяется |
| Ресурсы/период | товары по умолчанию пересчитываются, если не правили руками; сумма и формулы |
| Свежая занятость | заполненный Р может стать «ошибка» («Баня 1 заняли 14:00–16:00») |

## 3. Модель
`apps/web/src/bookings/booking-wizard-model.ts` — чистые функции: `initialDraft`, `visibleSections`,
`sectionView` (статус, сводка, бейдж, проблемы), `allIssues`, `applyChange` (редьюсер), `firstSection`,
`toCreateRequest`. Статусы раздела: `locked | empty | done | warning | error`; активный раздел — отдельно.

Сводка свёрнутого раздела (одна строка):
- Кто: `Иван Петров · #678 «Баня 25.10» · 🟢` / `· новая сделка` / `Служебная (без сделки)`
- Группа: `Бани · Визит`
- Ресурс и время: `Баня 1 · пн 27.10 14:00–18:00 · 4 ч`; interval: `Домик 2 · 27.10 14:00 → 29.10 12:00 · 2 ночи`
- Сертификат: `10 000 ₽ · электронный · на Петрова И. · до 26.10.2027`
- Товары: `3 поз. · 13 400 ₽ · Предоплата · «Парение»`
- Поля: `Заполнено 7 из 9 · очищено 2` или красный бейдж `Не заполнено 2: Гостей, Программа`

Значки: done — зелёная галочка; warning — жёлтый треугольник + бейдж; error — красный «!», красная
полоса слева, бейдж; locked — серый текст-подсказка; empty — «Не выбрано».

## 4. Раскладка
Одна колонка-аккордеон, без правой панели. Ширина до 760px, высота до min(92dvh, 960px), прокручивается
тело. Шапка 52px «Новая бронь · Бани · Иван Петров» [свернуть][×]. Свёрнутая строка 44px (телефон 48px):
`иконка | название 132px | сводка | Изменить`, вся строка — кнопка. Активный раздел — рамка primary,
внизу «Далее →» (или «К проверке»). Футер 56px закреплён: слева живая сводка (ресурс · дата/время ·
итог ₽), справа «Отмена» и главная кнопка «Далее» → «Проверить» → «Создать бронь». Выбор даты
— в разделе Р (2026-10-26, см. ниже). Телефон ≤560px: на весь экран, строка в две строки, товары
карточками, футер с safe-area. CALL_CARD: футер сверху, строки 40px, компактный выбор времени.

## 5. Проверка и подтверждение
Открывается, только если нет ошибок (иначе — открыть раздел первой ошибки и фокус на поле). Карточка-
«чек» только для чтения: Клиент, Сделка, Группа, Ресурс, Когда, Товары (строки, скидка, итого), Оплата,
Поля сделки (непустые; обязательные — полужирным), Комментарий; у строк «Изменить». Ниже
предупреждения (жёлтые): тех. окно (бронь возможна), по сделке уже есть бронь, тип брони не определится.
Кнопка «Создать бронь», рядом «с предупреждениями: 2».

Ошибки создания: 409 пересечение / стоп ресурса → Р; «уже создаётся» → «Проверить результат» (тот же
ключ); 503 → «Повторить»; поля → П; права → К/Г; тип брони → Т. Ключ идемпотентности — один на окно.
Частичный сбой (бронь есть, поля/товары нет) — экран результата «✔ Бронь #555 создана» + предупреждения
+ «Открыть сделку / Перейти к предоплате / Готово».

## 6. Товары, допы и оплата
1. «Основное» — товары ресурса по умолчанию (метка `по умолчанию · Баня 1`); у существующей сделки — её
   строки и плашка «Изменения заменят товары сделки #678».
2. Панель «Допы»: поиск + теги разделов каталога (первые 4, остальные под «Ещё ▾») + «Весь каталог»;
   у тега счётчик выбранного `Веники · 2`, выбранный — мягкая заливка primary.
3. Таблица выбранного (ПК): `Товар | − N + | Цена | Скидка %/₽ | Сумма | ×`; изменённая цена — метка
   `изм.` (подсказка «Каталог: 3 500 ₽», ↺); скидка — старая сумма зачёркнута; новые строки на 1 с
   подсвечиваются. Телефон — карточки: `название ×` / `− N +  цена  = сумма` / «Скидка…».
4. Итоги: без скидки / скидка / итого.
5. «Бронь и оплата»: тип брони (список или карточки), способ оплаты, ссылка на оплату и сумма
   предоплаты (сертификат), «Гостей», если нет поля-роли.

**Окно каталога** (`CatalogDialog`, нативный `<dialog>`): слева разделы «Все» + разделы каталога с числом
товаров и точкой-счётчиком выбранного (телефон — лента чипов сверху); справа товары раздела (вложенные
тоже); поиск — по всему каталогу, с подписью раздела. Строка: название · цена (`без цены` серым) · «+»
или степпер `− N +` (выбранная — мягкая заливка и полоса 3px слева); 0 — убрать. Цена и скидка в окне
не правятся. Футер: «Выбрано: 3 позиции · 2 350 ₽» [Готово]. Esc закрывает только окно. Пока товары
сделки не загружены — кнопки каталога недоступны с подсказкой.

## 7. Окна
Не больше одного окна поверх конструктора: каталог, «Оставить/Очистить» поля сделки (при первом входе в
П или перед проверкой), выбор времени (звонок), «Сбросить изменённые товары?».

## 8. Обязательные поля
- Пометка: красная `*` у метки (`aria-required`), в заголовке П «обязательных: 3». Пустое не краснеет,
  пока не трогали.
- Подсветка — после ухода с раздела, потери фокуса пустым или нажатия «Проверить»: рамка `#d92d20`, фон
  `#fef3f2`, подпись «Обязательное поле». В паре «2 в линии» — только пустая ячейка. Уйти с раздела
  можно (сворачивается со статусом «ошибка»), нельзя — на проверку. Заполнили — красное снимается сразу.
- Сводка: красный «!» + `Не заполнено 2: Гостей, Программа` (+N); клик — раздел и фокус на поле.

## 9. Поля сделки
- Показываем поля «С» группы, кроме типа брони; поля, которые заполняет приложение (ID/даты брони,
  ссылки, счета), скрыты; прочие «только чтение» — компактно «подпись: значение» внизу.
- Порядок и «2 в линии» — из настроек; многострочный текст — всегда во всю ширину. Предложение:
  необязательный «Заголовок блока» у поля (подзаголовок капсом + линия).
- Метка над полем 12.5px, контрол 36px (32px в CALL_CARD).
- Контролы: число — для «гостей» степпер; деньги — разделители тысяч, ₽, вправо; список до 5 коротких
  вариантов — сегментные чипы, иначе select; да/нет — сегмент «Да | Нет» (+ «—»); дата — «сегодня /
  дата брони»; формула — ƒ «авто», изменённое вручную — точка и ↺; значение по умолчанию — метка.
- Сумма сделки — «из товаров» со ссылкой на Т.

## 10. Реализация (этапы)
0. Макет → согласование. 1. Модель + тесты (матрица входов, сбросы, сводки, проблемы, тело запроса).
2. Загрузка данных (`useWizardData`) + новая оболочка. 3. К, Г, Р, проверка, экран результата.
4. Т + окно каталога. 5. П (контролы, скрытие системных, заголовки блоков). 6. Удаление старого
мастера, телефон, CALL_CARD, документация. Контракт `POST /bookings` и пропсы `BookingForm` не меняются.

## 11. Открытые вопросы (по умолчанию)
1. «Оставить/Очистить» — окном (как сейчас) при входе в П или перед проверкой.
2. В режиме «часы» количество почасового товара по умолчанию следует за длительностью — да, пока не правили.
3. «Доп. услуги» — порядок тегов из ⚙, без новой настройки.
4. Заголовки блоков полей сделки — да, этапом 5.
5. Экран результата при частичном сбое — да, только при предупреждениях.

## Раздел «Ресурс и время» (решение владельца 2026-10-26)
- Дата — не в разделе Г, а посередине раздела Р (`DatePicker`): крупная дата со стрелками ‹ ›, неделя
  вокруг неё для быстрого перехода, по нажатию на дату — календарь месяца («Сегодня», «Завтра»).
- Почасовые группы: нет кнопок −30/+30, длительности и полей начала/конца. Время задаётся нажатием на
  шкалу ресурса — окно «Время брони» с началом и завершением от места нажатия (длительность прежняя или
  группы). «Заезд/выезд»: время заезда, ночи и выезд остаются, шкала выбирает ресурс.
- Шкала: занятое время красное (`#f04438`), тех. окно жёлтое. Выбранный период не рисуется поверх
  всех шкал — только у выбранного ресурса и только при наведении на его шкалу.

## Клиент обязателен (решение владельца 2026-10-26)
У клиентской брони и у новой сделки сертификата всегда есть контакт. Поводом стала сделка 40012: бронь создали
из чата без контакта в CRM — сделка получила имя клиента в названии, но без контакта, и окно оплаты
не нашло чатов клиента.
- Мастер: сделка (новая или выбранная) без клиента — раздел «Кто» открыт с ошибкой «Выберите
  клиента», поиск клиента показан сразу; проверка и создание без клиента невозможны.
- Выбранная сделка без клиента (встройка, чат) при выборе клиента не меняется: при создании брони
  контакт привязывается к ней основным (`crm.deal.contact.add`, `IS_PRIMARY=Y`).
- «＋ Новый клиент» в поиске: имя и телефон → `POST /api/crm/contacts`; контакт с этим номером уже
  есть — возвращается он (дубль не создаётся).
- Сервер: `POST /bookings` (kind=client) без контакта в заявке и у сделки — 400 `CLIENT_REQUIRED` до
  любых записей в Битрикс24; `POST /certificates` с новой сделкой без контакта — то же.
