# Клиент, сделки и каналы переписки

В «Чатах» доступен фильтр канала: собственный и провайдерский WhatsApp входят в одну группу.
Канал действует на количество, пагинацию и поиск по номеру. В диалоге можно выбрать другой
доступный канал этого клиента. Все диалоги положительно проверяются правами сотрудника.

Номера +7/7/8 и десять цифр РФ сопоставляются с одним клиентом, включая городские номера.
Поиск CRM выполняется средствами Битрикс24; контакты, компании и активные сделки не создаются
сервисом сопоставления. Интерфейс получает только CRM-объекты, доступные текущему сотруднику.

Собственный мессенджер хранит выбранную сделку клиента. Одну активную входящее выбирает само,
несколько — сотрудник. В переписке номера есть «Текущая сделка» и «История» (вся/без сделки/по
конкретной сделке). Переключение не переносит старую переписку: назначаются только сообщения,
ожидающие выбора. Завершённая сделка доступна в истории, для новых сообщений нужна активная.
Импорт прежней истории не привязывает её к сегодняшней сделке.

Для своей ОЛ выбор входящей сделки также доступен в обычном ChatView; «Переписка по сделкам»
открывает тот же диалог номера. Первая сделка переиспользует существующий диалог. Следующая
получает отдельный virtual chat ID. Правки и удаления возвращаются в исходный диалог сообщения.
Связь со сделкой сохраняется в приложении; поля существующих карточек CRM не переназначаются.

Если звонок без диалога, в блоке «Звонки» дашборда и во встройке звонка есть кнопка поиска в мессенджерах
(`MessengerSearchButton`): после нажатия — значок каждого доступного номера-мессенджера; пока идёт проверка — бегущие
точки, найден — «1» как у уведомления (нажатие открывает переписку), не найден — красный крестик; ↻ — искать заново.
Окно проверяет только номера разрешённых групп: «найден», «не найден», «проверка недоступна».
Никаких пробных сообщений. Сотрудник может продолжить доступный существующий CRM-диалог или
выбрать новый подключённый канал. Новый канал к найденному клиенту не создаёт ОЛ автоматически:
входящее видно в приложении, сотрудник выбирает/применяет сделку, нажимает «Работать в этом канале»
либо пишет клиенту. При выборе канала ожидающие входящие передаются в ОЛ, исходящих клиенту нет.

Собственные номера в списке мессенджеров доступны по группам/read/send; существующие ОЛ
проверяются user.client. Чужие провайдерские подключения не становятся нашим каналом доставки.
Telegram по решению владельца отложен. Подключены только WhatsApp.

Проверки: полный npm run check (862), затем проверки дополнительных регрессий API (562 API
теста), typecheck/lint/build для изменённых workspace. Browser local/public: оба оформления и
ширины, поиск без отправки, выбор сделки/фильтр истории/вложения; CALL_CARD short/mobile/desktop.
На портале read-only: все4формата номера →1контакт/2активные сделки, два номера WA нашли клиента,
4существующих диалога, оба подключения ready. Новых реальных исходящих для тестов не отправляли.

## Редактор сообщения, шаблоны, сделка в шапке и аватарки (2026-10-25)

- **Редактор.** Вложения — значками в правом верхнем углу поля: скрепка (с устройства) и значок
  Битрикс24 (с Диска); без подписей, строки о лимитах и «+ ещё сообщение в цепочку» (цепочку по-прежнему
  даёт шаблон из нескольких сообщений). Справа — «Отправить», под ней — «Шаблоны».
- **Шаблоны.** Окно: сверху «＋ Новый шаблон» (название, сообщения, вложения), ниже — шаблоны чата по
  частоте вставки сотрудником за 30 дней (`uses30d`; каждая вставка — `POST /openlines/templates/:id/use`,
  запись `template.use` в журнале действий). Ссылка «Изменить или удалить шаблоны» — прежний менеджер.
- **Сделка в шапке.** Карточка как выбранная сделка в мастере брони (цвет по брони, название, сумма,
  номер, дата, бронь); нажатие открывает сделку. У чата своей линии с несколькими открытыми сделками —
  ⇅: окно выбора сделки входящих сообщений (`PUT /messengers/openlines/:chatId/deal`). Прежний селектор
  «Сделка входящих сообщений» и кнопка «Переписка по сделкам» убраны.
- **Аватарки.** Список чатов и шапка показывают фото клиента из Битрикс24 (`clientAvatar`). Для чатов
  приложения фото берёт сервис мессенджеров (`POST /instances/:id/avatar`: WhatsApp — фото профиля,
  Telegram — `photos.getUserPhotos`, MAX — ссылка из контакта; хранится неделю) и передаёт в линию как
  `user.picture` при пересылке сообщений клиента. У существующих чатов фото появится с ближайшим
  сообщением клиента.
- **Вкладки.** ∞ «Все», «Без ответа», «Брони», «Оплата».

## Шапка чата, «Чаты клиента», Диск по умолчанию (2026-10-26)

- **Сделка в шапке** — одной строкой, в виде тегов каналов (без цветов брони): название до 15 символов
  (полное — в подсказке), сумма, «бронь ДД.ММ.ГГГГ» или, без брони, «от ДД.ММ.ГГГГ» (создание сделки).
  ⇅ — внутри блока справа; окно выбора сделки — прежнее, как в мастере брони.
- **Теги клиента** («Сделок», «Ср. чек», «Броней», «Ближайшая») и «+» — того же вида: белые, тонкая рамка,
  высота 24 px; «Идёт сейчас» выделяется только красным временем.
- **«Чаты клиента»** (кружок «+N»): строки как «Последние сообщения» дашборда (канал, аватар, имя,
  пузырь с последним сообщением и временем, непрочитанные) и две кнопки — «Сделка» и «Перейти в чат».
  `GET /openlines/chats/:chatId/channels` дополнительно отдаёт `clientName`, `clientAvatar`, `preview`,
  `hasFiles`, `unread`, `dealId`.
- **Выбор файла с Диска** открывается в папке «Общий диск / БК Алатырь / Шаблоны сообщений / Шаблоны
  приложения» (`DISK_TEMPLATES_PATH`); если её нет или у сотрудника нет доступа — на «Моём диске».
  Переключатель «Общий диск | Мой диск» вверху окна. `GET /openlines/disk/start` (токен сотрудника,
  запоминается на 10 минут) — путь к папке и корень «Моего диска».
