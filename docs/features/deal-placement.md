# Встройка сделки: чаты · шкала броней · быстрые действия

Решение владельца 2026-10-26 (заменяет «Чат с клиентом · Календарь · Новая бронь» того же дня).
Из карточки сделки приложение открывается экраном из трёх блоков в стиле дашборда
(`apps/web/src/deal/DealHome.tsx`). Открытие не из сделки — как раньше (дашборд).

- **Слева — чаты клиента** (`GET /api/openlines/deal-chats/:dealId`, правами сотрудника). Больше одного —
  список строками «Последних сообщений» дашборда («!» и «⋮»: сделка, перейти в чат, скрыть с дашборда);
  нажатие открывает только чат, к списку — «назад» слева сверху (видна и на широком экране), рядом —
  «обновить» (перечитать чат и список; есть и в заголовке списка). Чат один и рабочий — сразу он, «назад» —
  к списку (2026-10-27). «Присоединиться» сбрасывает сохранённый доступ к чату и кэш ленты — поле ввода
  появляется сразу, а не через 5 минут.
  Чат в неработающей линии (`lineProblem` из `line-health.ts`: линия выключена, канал не подключён, или
  уведомление Wazzup «канал выключен») сам не открывается: в списке он с кнопкой **«Создать новый чат»**,
  а если рабочих чатов нет — ещё и красное предупреждение с той же кнопкой (2026-10-26). Окно
  `DealNewChatDialog` (`GET /api/messengers/deal-targets/:dealId`) показывает подключения со своей линией
  и адрес клиента в каждом: уже связанный с контактом чат → ID Telegram из карточки (поле Wazzup) →
  логин Telegram → телефоны контакта. «Написать» шлёт первое сообщение с `forDeal`: клиент чата — контакт
  сделки, и линия связывает новый диалог с ним, а не создаёт нового клиента (см. `messengers/MODULE.md`).
- **Справа сверху — «Счета клиента»** (`ClientInvoicesBlock`, `GET /payments/client-invoices?dealId`,
  2026-10-26): счета всех сделок контакта — ждут оплаты (заявка приложения ещё идёт или счёт открыт) или
  оплачены, пока не закончилась бронь счёта (без брони в заявке — бронь его сделки). Тонкая строка: тег
  «Эта сделка» / «Другая сделка #N» (оранжевый), сумма, дата и время, основание, «Ссылка: ещё 1 ч 20 мин»
  (срок — только у счетов приложения) или «Оплачен»; клик — счёт в Битрикс24. Виден с правом `payment.send`.
- **Под ним — шкала броней** (`ResourceTimelineBlock` дашборда): группы воронки сделки
  (`MyGroupDto.dealCategoryId` = воронка сделки из `/deals/:id/bookings`; не определилась — все группы
  с календарём), дата с ‹ ›, «Сегодня», масштаб, переключатель групп кнопками рядом с заголовком.
  Клик по свободному времени — мастер брони по этой сделке.
- **Справа снизу — быстрые действия:**
  1. **Получить оплату** (`payment.send`, зелёная) — окно `PaymentDialog`: вкладки «Произвольная» (по
     умолчанию: основание с быстрым выбором, сумма, срок ссылки 1–24 ч, текст «Просим Вам произвести
     оплату {{СсылкаНаОплату}}»), «Предоплата», «Доплата» (как раньше, по настройкам группы). Внизу —
     история счетов. См. `apps/api/src/modules/payments/MODULE.md`.
  2. **Мастер бронирования** (`booking.create`) — поверх встройки; если по сделке уже есть бронь —
     прежнее предупреждение «Создать новую сделку / Игнорировать».
  3. **Шаблоны** (оранжевая) — открывает чат клиента (если открыт список — самый свежий чат) и окно «Шаблоны»;
     шаблон вставляется в поле, отправляет менеджер.
- Экраны «Сделка» (`/deals/:dealId/overview`) и «Календарь» из встройки не открываются; код остался.

# «Чаты»: «+ Добавить»

Кнопка «Мессенджеры групп» (📱) убрана; на её месте — зелёная «+ Добавить» (право писать). Окно
«Новый диалог» (`NewDialogDialog`): номер телефона (все мессенджеры) или логин Telegram (`@имя`,
`t.me/имя`) → у каждого подключения статус проверки (проверяем / найден / не найден / недоступно) →
«Начать чат». Есть чат в своей линии — откроется он; нет — окно первого сообщения. Проверка ничего
не отправляет клиенту.
