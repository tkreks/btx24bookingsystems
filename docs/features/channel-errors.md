# Ошибка отключённого канала Wazzup

2026-10-25: в списке чатов и открытой переписке различаются подписи «WhatsApp/Telegram · Wazzup»
и «WhatsApp/Telegram · Приложение». Чужой диалог не превращается в собственный канал.

Если превью последнего сообщения содержит `=== SYSTEM WZ === Ошибка отправки сообщения:
канал выключен`, у чата показывается «Ошибка канала». Поддерживается уведомление, дописанное
к тексту исходящего сообщения. В открытой загруженной истории такое уведомление показывает
панель восстановления, даже если после ошибки уже были другие сообщения.

Это признак обнаруженной ошибки отправки, а не живая проверка Wazzup и не постоянная отметка
в БД. В списке метка зависит от текущего превью; в переписке — от загруженных сообщений.
Старая ошибка после восстановления подписки не доказывает, что канал всё ещё отключён.
Текст уведомления не меняет прав, статусов и доступности отправки.

2026-10-25, правка владельца: панель — заметная плашка ошибки (красная, треугольник «!»). В списке
чатов у такого чата рядом с именем клиента — тег «⚠ Ошибка» (`ChannelErrorTag`).

Панель позволяет открыть уже существующую собственную ОЛ того же мессенджера, доступную
сотруднику через штатный `/channels`, либо «Начать новый диалог». Один номер у клиента — номер не
показывается, сразу окно проверки в мессенджерах (`NewDialogDialog`, статус у каждого подключения);
несколько — выбор номера списком; номера нет — поле ввода в том же окне. В режиме восстановления
проверяются только собственные подключения ОЛ в состоянии ready, без старых диалогов Wazzup.
Права на номера и диалоги по-прежнему проверяет сервер.

Кнопки открывают нужную переписку или редактор первого сообщения. Сообщение отправляется
только явной кнопкой менеджера; старый неудавшийся текст не повторяется автоматически.
История старого диалога сохраняется. Если новой переписки нет, используется существующий
путь первого контакта MessengerChatsService.send → MessengerConnectorService.firstContact.

Пример диагностики контакта140: старый wz_telegram чат14034 содержит уведомление об ошибке;
собственные чаты50856 (Telegram) и50848 (WhatsApp) уже существуют. Подключения WA14/18 иTG16
имеют ready и lineMode=own. Сообщения клиенту при диагностике не отправлялись.

## Плашка «Канал Wazzup выключен» — три выхода (2026-10-25)

- **Перейти в чат** — чаты клиента в подключении приложения (`btx24_*`): один — открывается сразу,
  несколько — окно выбора чата.
- **Начать новый чат** — показывается, только если клиент найден в том же мессенджере (проверка
  `GET /messengers/search` при открытии плашки, клиенту ничего не уходит). Несколько аккаунтов
  мессенджера, где клиент найден, — сначала выбор аккаунта.
- **Найти клиента** — поиск по мессенджерам, где чата с клиентом ещё нет (работающие свои линии).

Новый чат создаётся в «Чатах»: первое сообщение уходит через свою линию (`firstContact`), ответ
`POST /messengers/:id/send` содержит `openlineChatId`, и веб открывает этот чат открытой линии, а не
окно мессенджера. Номер без своей линии — по-прежнему окно мессенджера.

## Поиск клиента — по мессенджеру, а не по аккаунту

Во всех окнах поиска (`NewDialogDialog`, `MessengerSearchDialog`, значки `MessengerSearchButton`)
один значок/строка на мессенджер (WhatsApp, Telegram, MAX), сколько бы аккаунтов ни было подключено
(`messengers/by-kind.tsx`, `groupByKind`). Найден хотя бы в одном аккаунте — «найден»; при нажатии,
если аккаунтов с найденным клиентом несколько, спрашиваем, через какой писать (`AccountPicker`).

## Встройка сделки: предупреждение и поиск в блоке «Чат с клиентом» (2026-10-26)

Если у клиента сделки есть чат с уведомлением Wazzup «канал выключен» (по последнему сообщению,
`/openlines/deal-chats/:dealId`), в блоке «Чат с клиентом» стартового экрана встройки — красное
предупреждение и сразу поиск клиента по мессенджерам по первому номеру клиента (значки WhatsApp,
Telegram, MAX со статусом). Отдельной плитки «Отправить клиенту сообщение» нет (убрана по решению
владельца в тот же день).
