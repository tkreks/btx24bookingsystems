# Сертификаты

## Зачем
Учёт подарочных сертификатов: кто купил, на кого, на какую сумму, до какого числа действует и чем
закончился (использован или истёк). Решение владельца 2026-10-23.

## Как работает (для пользователя)
Дашборд → 🎟 «Сертификаты». Список: номер, на чьё имя, номинал, дата оплаты, действует до, статус;
фильтр «Все / Новые / Срок прошёл / Использованы / Истекли» и поиск по номеру или имени.
- **Выпуск** — «+ Выпустить сертификат»: номер (пусто — следующий по порядку, или номер бумажного
  бланка), номинал, на чьё имя, дата оплаты (сегодня), срок (по умолчанию год; кнопки 3 мес. / 6 мес. /
  1 год), сделка и комментарий — необязательно.
- **Изменение** — в карточке «Изменить срок» (только у нового), с причиной.
- **Погашение** — «Погасить»: причина «Использован» или «Истёк»; после погашения сертификат не меняется.
- Новый сертификат с прошедшим сроком подсвечен «срок прошёл» — его гасят как «истёк».
- У карточки — история: выпуск, изменения срока, погашение (кто и когда).

## API (эндпоинты, контракты из @btx24/shared)
`GET /api/certificates?status=&q=` → `CertificateListDto`; `GET /api/certificates/:id` →
`CertificateDetailsDto`; `POST /api/certificates` (`IssueCertificateInput`); `PUT /api/certificates/:id`
(`ChangeCertificateInput`); `POST /api/certificates/:id/redeem` (`RedeemCertificateInput`).

## Данные (модели, ограничения БД)
`Certificate` (уникальный номер в портале, номинал > 0 — CHECK, даты — `DATE`), `CertificateEvent`
(история). Миграция `20261023000800_certificates`.

## Инварианты и граничные случаи

## Права доступа
Смотрят все с доступом к приложению; выпускают, меняют и погашают — администраторы приложения и
сотрудники с правом «ссылки на оплату» (`payment.send`) хотя бы в одной группе.
