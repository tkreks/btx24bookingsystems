# Шкала броней и поиск клиентов из дашборда

Обновление 2026-10-25.

## Сделки без открытой линии

У каждой сделки есть кнопка поиска клиента в мессенджерах, как у звонков. Телефоны берутся
из контакта и компании уже доступной сделки, только REST-клиентом сотрудника. Дубли телефонов
нормализуются (+7/8/7); при нескольких номерах рядом есть выбор. При отсутствии доступного
телефона кнопка отключена с пояснением — отказ CRM не превращается в раскрытие данных.
Поиск запускается явно; после него менеджер выбирает подключение, сделку при необходимости
и пишет приветствие. Сам поиск сообщение не отправляет. Доступ к номерам и существующим ОЛ,
а также право отправки проверяют штатные сервисы мессенджеров.

## Дата и ресурсы шкалы

Шкала имеет собственную дату, независимую от периода остальных показателей. По умолчанию —
сегодня, полные сутки 00:00–24:00 в поясе портала, включая уже прошедшие брони. Стрелки меняют
день; «Сегодня» возвращает к сегодняшнему дню и часовому масштабу. В прошлое новую бронь со
шкалы создать нельзя; существующие брони по-прежнему открываются для просмотра.

Режимы «7 дней» и «Период» (1–7 дней) показывают суточные ячейки вместо часовых полос.
Красный день — хотя бы одна бронь ресурса пересекает эти сутки, даже на одну минуту. Зелёный —
нет броней и стопов. Серый штрих — есть стоп (даже частичный, это не обещание доступности целого
дня). Если есть и бронь, и стоп, бронь остаётся красной с серым подчёркиванием; причина стопа
есть в подсказке. Нажатие суточной ячейки раскрывает выбранный день по часам. Интервалы [start,end).

Кнопка группы/ресурсов открывает карточки в стиле мастера брони: группы и кнопки ресурсов,
«Все ресурсы». Фильтр ресурсов локален; доступные группы по-прежнему задаются настройкой
дашборда. В списке ресурсов отмечено наличие стопа в выбранном периоде. Высота дорожек21px
вместо30px, часовые линии не перехватывают нажатия. Длинные шкалы прокручиваются горизонтально.

## Стопы

`GET /calendar` уже возвращает доступные стопы портала/ресурсов. Шкала использует эти данные:
стоп закрывает свободный участок и техокно, показывает причину и не открывает мастер брони.
Существующая бронь на фоне стопа сохраняется видимой. Сам техперерыв бронь не запрещает.
Период проверяется в поясе портала, не браузера. Серверная проверка стопов при создании брони
остаётся обязательной; UI её не заменяет.

Календарь перечитывается раз в минуту, при возврате фокуса и после изменений приложения.
Ответы предыдущих запросов не затирают более свежие. Период ограничен7днями, чтобы не
создавать десятки повторных запросов календаря; масштаб месяц в это изменение не входит.

Причина исходной ошибки с Теремком: шкала игнорировала CalendarDay.stops и раскрашивала ресурс
без броней как свободный, хотя стоп уже был в API. Изменение схемы/данных БД не требуется.

## Ближайшие и текущие брони (2026-10-25)

Блоки «Ближайшие брони» (`upcomingBookings`) и «Текущие брони» (`currentBookings`) —
`GET /api/dashboard/live-bookings?kind=upcoming|current` (право `calendar.view`, ресурсы групп
сотрудника). Текущие — брони, идущие сейчас (`start ≤ now < end`), ближайшие — начинаются в
следующие 14 дней, не больше 30. Брони берутся из журнала приложения; сделка, клиент с фото,
сумма и «внесённые оплаты» (поле из карты полей исхода) — из копии CRM с проверкой видимости,
недостающее — у портала токеном сотрудника. Одна строка: название, время (у текущих — «до»
окончания), ресурс, клиент, сумма, оплата (зелёный — полностью, жёлтый — частично, красный — 0).

По клику — карточка `GET /api/bookings/:id/info`: доступ — `booking.details` в группе, где есть
ресурс брони (или администратор), поля сделки — по настройке этой группы (как в календаре),
товары сделки, стадия, ответственный. Сделка без доступа в CRM — только сама бронь.

«Брони (шкала, текущие)» (`resourceTimelineNow`) — та же шкала в режиме `live`: сегодня, без
выбора даты и масштаба, только ресурсы с идущей сейчас бронью и только эти брони; синяя черта —
текущее время. Настройка групп — как у обычной шкалы (`groupIds`).

**Прошедшее время (2026-10-26).** Бронь со шкалы — только на будущее. На часовой шкале свободное время,
тех. окна и стопы до текущего момента закрашены серой штриховкой и не нажимаются (`withPast`,
`dashboard/timeline-data.ts`); брони остаются видны. В периоде прошедший день без брони — серый.
Действует на дашборде и во встройке сделки (общий `ResourceTimelineBlock`).
