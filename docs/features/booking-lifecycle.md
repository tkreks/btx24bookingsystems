# Бронь: от запроса клиента до оплаты (план, 2026-10-21)

Архитектура — ADR 0007 (предложено). Здесь — процесс менеджера и порядок реализации.

## Процесс менеджера (со слов владельца)
1. Клиент: «хочу забронировать» — дата, **программа**, **номер бани**, **сколько гостей**, комментарий.
2. Менеджер вносит это в форму приложения (из сделки или с выбором/созданием сделки).
3. Приложение считает **стоимость** и **предоплату** (сейчас фикс **25 000 ₽** — настройка группы).
4. Сохранение (сага, каждый шаг — в журнал операций и аудит):
   сделка (поля, товары) → локальная бронь `awaiting_payment` → бронь в Битрикс24 + связь со
   сделкой → смарт-счёт на предоплату + ссылка на оплату.
5. Клиенту в его чат открытой линии автоматически уходит сообщение по шаблону: ссылка на оплату
   + файлы (согласие на обработку данных и др. — **файлы с Диска Битрикс24**).
6. Запускается **таймер ожидания оплаты — 90 минут** (`paymentTimeoutMinutes` группы).
7. Оплата получена (событие изменения счёта `onCrmDynamicItemUpdate`, entityTypeId 31, + опрос
   как страховка) → таймер останавливается, бронь `confirmed`, сделка → стадия
   **«Ожидание клиента»**; в аудите — «Система: оплата получена».
8. Таймер истёк → «Система: автоматизация — удаление брони при неоплате»: бронь в Битрикс24
   удаляется, у нас `cancelled` / `payment_timeout`, оплата счёта удаляется (ссылка
   аннулируется), сделка → «В работе»; менеджеру — уведомление. Попадает в «Отменённые брони»
   дашборда.

## Порядок реализации
| Шаг | Что | Зависит от |
|---|---|---|
| 1 | Аудит: журнал событий брони (исполнитель, diff, источник), запрет правки в БД | — |
| 2 | Зеркало ресурсов + события ресурсов, сверка | — |
| 3 | Импорт броней Битрикс24 (онлайн-запись) + события броней; второй календарь в интерфейсе | 2 |
| 4 | Сверка и расхождения: запись, сообщение в чат, экран решения | 1, 3, чат |
| 5 | Форма брони: программа, баня, гости, комментарий; расчёт стоимости и предоплаты | правила цены |
| 6 | Сага создания (сделка → бронь → связь → товары) с компенсацией | 1, 5 |
| 7 | Счёт и ссылка на предоплату; сообщение клиенту с файлами Диска | 6, файлы |
| 8 | Таймер оплаты в worker, оплата → стадия, неоплата → отмена | 7, стадии |
| 9 | Перенос остальной автоматизации сообщений и типов покупки | 8 |

Шаги 1–3 можно делать сразу; 4–9 ждут ответов владельца (ниже).

## Ответы владельца (2026-10-21)
1. Чат расхождений — **новый** (⚙ → «Приложение» → «Создать чат уведомлений»).
2. Стоимость — пока на менеджере: товары с ценами, цену можно менять вручную.
3. Файлы: часть общая (общая папка на общем Диске), часть — своя у направления (своя папка).
   Нужен доступ приложения к Диску — право **«Диск» (`disk`)** в настройках локального
   приложения на портале и переустановка; до этого выбор файлов в настройках не сделать.
4. «Ожидание клиента» — в воронке «БК Алатырь»; 90 минут и 25 000 ₽ — только для неё, у домиков
   свои правила → настраиваются в группе (⚙ → группа → «Оплаты»).
5. Горизонт сверки — по умолчанию 180 дней (настраивается в ⚙ → «Приложение»).
6. Новая бронь из онлайн-записи (не через приложение) → уведомление в чат. Статусы: Новый,
   Просмотрен, Решено, Игнорировать; кнопки: открыть сделку, изменить бронь, отменить бронь.

Сделано: шаги 1–4 (аудит, ресурсы, импорт и сверка, уведомления), из шага 7 — настройки
предоплаты и текста сообщения клиенту. Дальше: 5–6 (форма и сага), 7 (счёт, ссылка, файлы), 8.

## Решения владельца (2026-10-21, второе уточнение)
- Приложение заменяет все БП; автоматические сообщения клиенту редактируются в приложении.
- Тип брони — по товарам; актуальны тексты, которые БП 270 слал в открытую линию.
- Имя ресурса для клиента — в приложении (`Resource.clientName`), без сопоставления с «Банный дом».

Сделано: ⚙ → «Ресурсы» (имена для клиента); ⚙ → группа → «Типы брони и сообщения клиенту»
(ключевые слова, поле «Тип бронирования», программа, цепочка «текст + файлы Диска», пример,
перенос из БП); «Оплаты» — тексты ссылки на оплату и снятия брони. Дальше — форма брони, сага,
системные поля сделки, отправка цепочек.

## Бронь кликом в календаре (2026-10-22, как в прототипе)
Форма брони открывается не только кнопкой «+ Бронь», но и из самого календаря — с уже
выбранными ресурсом и началом (конец — по режиму группы: «часы от клика» или «заезд/выезд»):
- **Календарь** — клик по пустому месту колонки ресурса; начало — получас под курсором
  (подсказка «+ 15:30» при наведении). Клик по брони открывает её карточку, как раньше.
- **Доступность** — клик по свободному куску или тех. окну шкалы; начало — получас в месте клика,
  но не раньше начала куска (после тех. окна — с его конца).
- **Список** — кнопки «+ ресурс» (время по умолчанию группы) и клик по тех. окну (с его начала).
Тех. окно бронь не запрещает — сервер вернёт предупреждение. Клики работают только в группе, где у
сотрудника есть право `booking.create`; без него календарь только для просмотра.

## Поля сделки группы в форме и карточке брони (2026-10-22)
- Форма брони показывает все поля группы с флагом «С» (⚙ → группа → «Поля сделки») по их типу:
  число, деньги, текст, список, да/нет, дата; «два в строку» — в одной строке; обязательные — со
  звёздочкой. У существующей сделки поля заполнены её значениями. Если среди полей есть «гости» и
  «комментарий менеджера» (системные роли), отдельные поля «Гостей» и «Комментарий» не показываются.
- Карточка брони: кнопка «Редактировать» (право `booking.edit`) — поля «С» и «П» становятся
  редактируемыми; «Сохранить» пишет в сделку только изменённые. Поля, которые заполняет
  приложение (ID и даты брони, тип брони, счета, ссылки), и составные поля — только для чтения.

## Снятие брони и новая форма брони (2026-10-22)
- Карточка брони: «Снять бронь» (право `booking.cancel`) → подтверждение с причиной → бронь
  удаляется в Битрикс24 и из календаря, в журнале — статус «отменена» и запись в истории.
- Форма брони: ресурс — выпадающий список (＋ ещё ресурс — редко нужно несколько); сделка —
  карточки: сделка, из которой открыли, или последняя сделка клиента сверху, остальные — «Показать
  ещё», внизу «＋ Создать новую сделку» и «Служебная бронь без сделки». Секции «Когда и где»,
  «Сделка», «Бронь и оплата», «Поля сделки»; кнопки — закреплены внизу окна.

## Поля сделки: порядок, «2 в линии», значения по умолчанию, формулы (2026-10-22)
- ⚙ → группа → «Поля сделки»: порядок (↑↓), «обяз.», «2 в линии» (поле и следующее — в одном
  ряду), С / П / О, «Значение» → **по умолчанию** (списки — выбором варианта) и **формула** для чисел
  и сумм. Внизу — предпросмотр раскладки карточки создания.
- Значение по умолчанию ставится в форме создания брони, только если в сделке поле пустое.
- Формула: `{OPPORTUNITY} * 50%` — 50% от суммы; знаки `+ - * / ( ) %`, ссылки — только на поля
  группы (проверяется при сохранении, `checkFormula` в `@btx24/shared`). В форме поле считается само,
  пока менеджер не изменит его руками; «↺» возвращает расчёт. В карточке брони («Редактировать»)
  формула досчитывает только пустые поля.
- Форма брони: секции «Когда и где», «Сделка», «Бронь и оплата», «Поля сделки»; сводка
  «ресурс · время · длительность» и кнопки — внизу окна; на телефоне — одна колонка.

## Клиент, сделка и товары в форме брони (2026-10-22)
- Из календаря клиента нет — форма сразу предлагает поиск: «Клиент» (телефон, e-mail, ФИО, ID
  контакта) или «Сделка» (название, имя клиента, ID); от 2 символов. Выбран клиент — его сделки
  (открытые — первыми), по умолчанию последняя открытая, иначе новая сделка на этого клиента.
- «Товары»: поиск по товарам разделов каталога группы, количество и цена в строке, итог. У
  существующей сделки показываются её товары (изменения заменяют строки сделки), у новой — товары по
  умолчанию выбранных ресурсов («заезд/выезд» — × число ночей). Сумма сделки в полях — по товарам.
  Тип брони у новой сделки с товарами можно не выбирать — определится по товарам.

## Мастер создания брони (2026-10-22, дизайн — `docs/prototype/ui/booking-wizard.html`)
Шаги зависят от того, откуда открыли (`wizardSteps`):
- **из меню / маркетплейса**: «Клиент и сделка» → «Группа» → «Дата и ресурс» → «Товары и поля»;
- **из сделки**: без первого шага; **одна доступная группа** — без шага группы; **клик в календаре**
  (ресурс и время известны) — без шагов группы и даты.
- **Переход по шагам** (решение владельца 2026-10-23): любой шаг в полосе шагов — кнопка: пройденные —
  посмотреть или поменять, следующие — если шаги по пути заполнены; иначе мастер остаётся на первом
  незаполненном с подсказкой.
1. *Клиент и сделка*: поиск клиента (телефон, e-mail, ФИО, ID) или сделки; без клиента — 20 открытых
   сделок с последней активностью (`LAST_ACTIVITY_TIME`: чаты, звонки, дела) в воронках групп
   сотрудника (`GET /api/crm/recent-deals`); новая сделка для клиента; служебная бронь.
2. *Группа*: плитки доступных групп, группа воронки сделки — первой.
3. *Дата и ресурс*: лента дней, календарь группы — клик по свободному месту ресурса; карточка слота:
   время, быстрые длительности, «свободно / тех. окно — можно / занято».
4. Если в сделке уже заполнены поля формы — диалог «Оставить / Очистить» по каждому полю. Сверху
   (2026-10-26): «Оставить все» и «Очистить все» — сразу дальше; «Продолжить» — по выбору у полей.
5. *Товары и поля*: ресурсы карточками (свободен / занят до …), время; товары — таблица: количество
   −/+, цена, скидка % или ₽ на единицу (`discountType`, `discount` → `DISCOUNT_TYPE_ID/RATE/SUM`,
   `PRICE` — итоговая), итоги; тип брони и оплата; поля сделки группы.

## «Сумма внесённых оплат» (2026-10-22)
Роль системного поля `paidAmount` (по названию «Сумма внесённых оплат», если не задана в ⚙). Значение
**пересчитывается заново** (`PaidAmountService`), а не прибавляется: по всем счетам сделки
(`crm.item.list` 31, `parentId2` = сделка) — сумма проведённых оплат счёта (`crm.item.payment.list`,
`paid = Y`); счёт отмечен «оплачен» вручную без оплат — его сумма. Когда: сразу после оплаты / отмены /
истечения срока по счёту приложения и раз в 5 минут — сделки, у которых менялись счета (в т.ч. выставленные
вручную в Битрикс24) или заявки на оплату (`PaidAmountJob`). В форме поле только для чтения. Счёт
приложения привязан к сделке (`parentId2`), в названии — сделка и бронь: «Счёт на предоплату по сделке
#678, бронь #555» (у клиента бывает несколько сделок в разных воронках).
